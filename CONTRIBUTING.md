# Working Agreement

These rules come from T1.1 of the plan. Amend this file by PR if the team agrees on something different at kickoff.

## Branches

- `main` is protected: no direct pushes, and every PR needs **1 approving review from a member who doesn't own that component**.
- Branch names: `feature/<taskid>-<short-name>`, for example `feature/t3.2-instrumentation` or `feature/t6.2-prometheus-config`.
- Fixes: `fix/<short-name>`. Docs only: `docs/<short-name>`.

## Workflow

```bash
git switch main && git pull
git switch -c feature/t3.1-flask-app
# ... work, commit small and often ...
git pull --rebase origin main          # stay current, resolve conflicts locally
git push -u origin feature/t3.1-flask-app
gh pr create --fill                    # or open the PR on github.com
```

- Keep PRs small (ideally one task each) and merge daily, so they're easier to review and conflict less.
- The reviewer **runs the change locally**. This is how everyone learns the whole system.
- Use squash-merge, with the task ID in the title: `T3.1: Flask app with business endpoints`.

## Commit messages

```text
T3.2: add request latency histogram

Uses the route template as the endpoint label to keep cardinality bounded.
```

## File ownership

Each file has one owner (plan Section 5.3). To change someone else's file, open a PR and request their review.

| Area | Owner |
|---|---|
| `app/`, `k8s/app/{00,10,20,30}-*`, `ansible/roles/app_deploy/`, `grafana/dashboards/app-overview.json`, `scripts/chaos.sh` | M1 |
| `scripts/bootstrap.sh`, `ansible/` (structure, playbooks, `common`, `docker`, `k8s_tools`, `minikube_cluster`), `k8s/app/05-limits-quota.yaml`, kube-state-metrics, Grafana manifests, `grafana/dashboards/k8s-workloads.json`, `README.md` | M2 |
| `docs/CONTRACT.md`, `scripts/loadgen.sh`, `scripts/scale.sh`, `k8s/app/40-loadgen.yaml`, Prometheus + node-exporter manifests, `ansible/roles/{monitoring,verify}/`, `grafana/dashboards/node-platform.json`, `docs/TEST_REPORT.md`, `docs/diagrams/` | M3 |

## Contract changes

`docs/CONTRACT.md` is frozen once approved. Adding something needs one approval. **Renaming or removing** something needs approval from all three members.

## Never commit

- Plain-text passwords or the Vault password (`ansible/.vault_pass` is git-ignored)
- `k8s/rendered/` (generated by Ansible)
- `latest` image tags

## Meetings

- Syncs: twice a week, 30 min (days agreed at kickoff). Includes a 20-minute teach-back on Thursdays.
- Integration sessions: 2 h, all three present, at each milestone IM1–IM5 (plan Section 6.4).
- Notes go in `docs/meeting-notes/YYYY-MM-DD-<topic>.md`.
